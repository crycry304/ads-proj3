\begin{abstract}
This project reconstructs an unknown fence layout from connector degrees.
Fences may span empty positions, while horizontal and vertical fences may
cross only at a connector. We model every possible straight fence between
consecutive non-zero connectors and solve a degree-constrained selection
problem with pairwise crossing conflicts. The exact solver combines static
checks, event-driven degree propagation, immediate conflict rejection, a
rollback trail, and minimum-remaining-values (MRV) branching. Correctness is
checked against exhaustive small grids and an independent validator.
Across a deterministic 24-case benchmark corpus, all cases completed within
the 30-second safety timeout. The maximum observed median runtime was
331.9 ms. Conflict propagation reduced search from 39,888 to 162 nodes on the
largest planted case, while MRV was beneficial on medium conflict-heavy inputs
but not uniformly faster.
\end{abstract}

\noindent\textbf{Keywords:} recovering a layout; degree constraints; event-driven
propagation; MRV; conflict graph; exact search

\section{Introduction}

\subsection{Problem and objectives}

The input is an $n\times m$ grid. A positive value $k\in\{1,2,3,4\}$ denotes a
connector that must be incident to exactly $k$ fence segments. A zero means
that no connector exists. Each fence is a straight horizontal or vertical
segment. A fence may pass through empty positions, but horizontal and vertical
fences may cross only when the crossing position contains a connector.

The program must output the binary \texttt{up/down/left/right} states of every
connector in row-major order, or print \texttt{No Solution}. Solutions are not
unique, so any valid layout is accepted. The objective is to find a valid layout
or prove that none exists.

\subsection{Why the geometry requires a conflict model}

A common but incorrect simplification is to connect only adjacent non-zero
cells. Sample 3 disproves it: the connector in row 1, column 3 connects to the
connector in row 1, column 5 across an empty column. Therefore every possible
fence is a maximal straight segment between two consecutive non-zero connectors
in one row or one column.

Two such segments can cross inside an empty cell. If both were selected, they
would form a crossing without a connector, which the statement forbids.

\section{Data Structure and Algorithm Specification}

\subsection{Candidate graph}

Let $V$ be the set of non-zero connectors and $E$ the set of candidate fence
segments. In each row, sorted non-zero columns define horizontal segments
between consecutive connectors. In each column, sorted non-zero rows define
vertical segments analogously. For a connector $v$, let $E_v\subseteq E$ be
the set of incident candidates; $|E_v|\le 4$.

For each possible horizontal/vertical pair $(e,f)$, a conflict exists when the
two segments intersect strictly inside an empty cell. The conflict relation is
stored as a symmetric adjacency list. Because candidate intervals in one row
or column do not overlap, each empty cell contains at most one horizontal and
one vertical candidate, hence at most one conflict pair.

\subsection{Exact constraints}

Let $x_e\in\{0,1\}$ indicate whether candidate $e$ is selected. A valid layout
satisfies
\begin{align}
  \sum_{e\in E_v} x_e &= d_v && \text{for every }v\in V,\\
  x_e+x_f &\le 1 && \text{for every conflict pair }(e,f).
\end{align}
Every selected segment contributes one degree to each endpoint. Thus the total
number of selected segments is exactly $\frac{1}{2}\sum_v d_v$.

\subsection{Static checks}

The model is rejected before search when:
\begin{itemize}
  \item the total requested degree is odd;
  \item a connector has fewer incident candidates than its required degree;
  \item a candidate-graph component has odd degree demand or too few edges.
\end{itemize}
These checks are necessary conditions only. Passing them does not imply that a
solution exists.

\subsection{Event-driven propagation}

The solver stores an edge state in $\{\mathrm{UNKNOWN},\mathrm{SELECTED},
\mathrm{REJECTED}\}$. For each connector it maintains the number of selected
incident edges and the number of unknown incident edges. When an edge changes
state, both endpoint connectors enter an event queue.

For a queued connector $v$, let $s_v$ be its selected degree, $u_v$ its unknown
degree, and $d_v$ its required degree. The branch fails immediately if
$s_v>d_v$ or $s_v+u_v<d_v$. Otherwise:
\begin{itemize}
  \item if $s_v=d_v$, every unknown incident edge is rejected;
  \item if $s_v+u_v=d_v$, every unknown incident edge is selected.
\end{itemize}
Selecting an edge immediately rejects all crossing candidates. Those changes
enqueue their endpoints, so the propagation continues until a fixed point is
reached or a contradiction is found.

\begin{lstlisting}[caption={Incremental propagation at one connector}]
while queue is not empty:
    v = pop_vertex(queue)
    if selected[v] > required[v]: reject_branch()
    if selected[v] + unknown[v] < required[v]: reject_branch()

    if selected[v] == required[v]:
        reject_all_unknown_edges_incident_to(v)
    else if selected[v] + unknown[v] == required[v]:
        select_all_unknown_edges_incident_to(v)
\end{lstlisting}

\subsection{MRV branching}

After propagation reaches a fixed point, every unsatisfied connector has
\begin{equation}
  \mathit{need}_v = d_v-s_v,\qquad
  B_v=\binom{u_v}{\mathit{need}_v}.
\end{equation}
$B_v$ is the number of immediate local assignments for connector $v$. MRV
chooses the connector with the smallest $B_v$; since $u_v\le4$, $B_v\le6$.
Ties prefer more incident crossing conflicts and then the smaller internal
vertex id. MRV changes only the order of complete value enumeration and
therefore preserves completeness.

\subsection{Search and rollback}

At each search level, propagation is completed first. If every connector has
exactly its required degree, the first solution is returned. Otherwise MRV
selects a connector and enumerates every combination of exactly
$\mathit{need}_v$ unknown incident edges. The chosen edges are selected and the
other incident unknown edges are rejected. Every state change records its edge
id and previous state in a trail.

If a branch fails, the trail is rolled back to the branch checkpoint, restoring
edge states and both degree counters. The next combination is then tried. The
search is complete because every legal completion must choose one of the
enumerated local subsets.

\section{Analysis and Comments}

\subsection{Complexity}

Let $P$ be the number of connectors and $M$ the number of candidate fence
segments. Here $P\le 2500$ and $M<5000$. Building the connectors and candidate
edges takes $O(nm+P)$. Scanning the empty cells for conflicts takes
$O(nm+M)$, and the conflict graph contains at most $O(nm)$ pairs.

One propagation event processes at most four incident edges, but rejected
conflict edges may enqueue their own endpoints. If $W$ changes occur on one
search path, propagation costs $O(W)$ in that branch. Selecting the MRV variable
scans $P$ connectors and inspects four incident edges each, so one selection
costs $O(P)$.

If $N$ is the number of visited search nodes and $L$ is the cost of one node,
the search takes $O(NL)$. Branching remains exponential in the worst case.
It is therefore necessary to report measured node counts rather than only the
theoretical upper bound.

The no-propagation baseline completed 20 of 24 cases within a five-second
comparison limit; four large cases timed out. Degree-only propagation completed
all cases, while adding conflict propagation sharply reduced nodes on planted
inputs. MRV improved the medium planted and conflict-heavy cases but selected
an unlucky branch on the largest planted case.

\subsection{Comments and limitations}

MRV is a heuristic, not a guarantee of a smaller global subtree. The dense
all-positive graph has the same node count under fixed order and MRV, but MRV
incurs a full connector scan at every node. This overhead is visible in the
roughly 332 ms median against about 3 ms for fixed order.

The official problem statement gives no time limit. Results therefore describe
this machine, compiler, seed, and input corpus. A separate 50x50 planted probe
with density 0.50--0.55 exceeded a 15--30 second limit and is excluded from the
fixed acceptance corpus. This identifies dense random degree-constrained
instances as a limitation rather than claiming universal efficiency.

\subsection{Further improvements}

Future work can maintain the unresolved-connector set to avoid scanning all
connectors for MRV, add stronger forward checking after each local combination,
and use component decomposition when conflict edges do not couple candidate
components. A certified maximum bipartite subgraph solver could also provide
cheaper infeasibility bounds on bipartite components.
